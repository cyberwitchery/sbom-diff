# changelog

## Unreleased

- fix an empty value in an SPDX tag-value document, which spdx-tools writes as a bare `Tag: ` line for every empty text field, taking the line below it as its value: an empty `PackageVersion` took `PackageDownloadLocation: NONE` as the version, so a diff against the document's SPDX JSON twin, which carries `""`, reported the package as changed and labelled it `alpha@PackageDownloadLocation: NONE`; an empty `PackageDescription` or `PackageSummary` took the comment line below it as the description; an empty field that is never compared, such as `PackageFileName` or `PackageCopyrightText`, still swallowed the line below it; and an empty `RelationshipComment` or `AnnotationComment` on a document's last tag made the document fail to load. an empty value is now read as empty, as the JSON reader reads `""`, unless a `<text>` block on a later line is its value
- fix a crash (exit 101) on an SPDX tag-value license expression the SPDX expression parser rejects, such as `PackageLicenseDeclared: Apache License 2.0`, `MIT/X11`, `BSD-3-Clause, MIT` or `MIT AND`, on any of the five license tags, inline or in a `<text>` block: the run now stops with an error that names the line, the tag and the expression (exit 1), as it already did for the same expression in SPDX JSON, so a license gate never passes a license it could not read. a bad `ExternalRef`, `FileType`, `Relationship`, `AnnotationType` or checksum value in a `<text>` block crashed the same way, and `PackageChecksum: <text></text>` made the document fail to load; such a value is now skipped and named, as it already was when written inline. a valid value in a `<text>` block below its tag, such as `ExternalRef:` with `<text>PACKAGE-MANAGER purl pkg:cargo/alpha@1.0</text>` on the next line, was dropped with a false `'' is not an external reference category` warning, so the component lost its purl and its id; it is now read, as the same value on the tag's own line is
- fix a `#` comment line in an SPDX tag-value document changing how the lines around it were read: a bare `#`, with nothing after it, hid the next non-blank line, so `PackageLicenseDeclared: GPL-3.0-only` under one was never read and `--deny-license GPL-3.0-only` passed (exit 0), and a box comment (`#`, `# text`, `#`) above a package, or a bare `#` on the document's last line, made a valid document fail to load; a comment holding `<text>`, such as `# note: <text>see below`, hid the lines below it from the reader's checks down to the next `</text>`, so a `Creator:` there was dropped and named in the phantom creator warning, and a malformed license expression there crashed (exit 101). a `#` line is now a comment that ends with its own line
- fix a crash (exit 101) on an SPDX tag-value line with whitespace other than a space or a tab, such as a no-break space (U+00A0), after the colon of a `Relationship`, `ExternalRef`, `ExternalDocumentRef`, checksum or license tag, or between the fields of a `Relationship` or `ExternalDocumentRef`: the reader's checks skipped that whitespace, the parser does not. such a line is now skipped and named in the dropped-lines warning, and a license expression stops the run with an error that names the line (exit 1). an `ExternalRef` with it between its category, type and purl, or a checksum with it in front of the digest, was read without a warning but lost its purl or changed the digest; it is now skipped and named the same way
- fix a crash (exit 101) on an SPDX tag-value `ExternalDocumentRef` whose id holds a character other than an ASCII letter or digit, `.`, `-` or `+`, such as `DocumentRef-e_xt` or `DocumentRef-éxt`: the parser ends the id at that character and reads the rest of the line one field late, taking the document URI as the checksum. such a line is now skipped and named in the dropped-lines warning, as a bad checksum on that tag already is; one with no colon after its id, which made the document fail to load (exit 1), is skipped the same way

## [0.9.2] - 2026-10-25

- fix `--fail-on supplier-changed` failing on SPDX suppliers that differ from the other sbom's only in spelling: the email SPDX allows after the name, `Organization: Acme Corp (ops@acme.example)` against a CycloneDX `Acme Corp`, and an empty name, `Organization: `, `""` or tag-value `PackageSupplier: Organization:`, against no supplier. a supplier is now its name alone, so a changed email between two SPDX documents is no longer a supplier change, as changed CycloneDX contact details already aren't; spaces around a name are ignored, an empty name in either format, a CycloneDX `supplier.name` of only spaces included, is no supplier, and a parenthesized part that holds no `@`, such as `Acme (Europe)`, stays part of the name. a component without a purl whose SPDX supplier had an email or an empty name gets a new `h:` id, the same one its CycloneDX twin already had
- fix `--output text`, `markdown`, `csv` and `sarif` naming a component that has no purl by its raw `h:` id in the added, removed and changed sections, while the edge section of the same report calls it `name@version`: the OS component of every trivy image sbom read as `h:57746c80…  Version: 3.23.4 -> 3.24.3` instead of `alpine@3.24.3`, and in csv its `changed` row and its `edge-added` rows carried different keys. every section now uses the edge section's `name@version` (`name` without a version, its id with neither), sarif's `fullyQualifiedName` included, and two such components that share one each get a short id suffix, such as `busybox@1.37.0 (h:05a318d715f6)`. the `--fail-on`, `--allow-license` and `--deny-license` errors on stderr name components the same way, `removed component zlib@1.3.1` instead of `removed component h:afece572…`, dependency edges and cycles included; a license or cycle error, which covers the whole new sbom, adds the suffix whenever two components in it share a `name@version`, and a purl the sbom spells in a non-canonical form is printed as spelled in a component's own message but canonical in edge and cycle messages, as the report's component and edge sections print it. `--output json` is unchanged
- fix trailing spaces or tabs on a line of an SPDX tag-value document becoming part of the line's value everywhere but on the document's last line: a padded `Relationship` or `SPDXID` lost the dependency edge with a misleading `does not match any element` warning, a padded package name, version, purl or checksum showed the package as changed, or as removed and re-added, against the same document without the padding, and a padded `FileType` was skipped as unreadable. the whitespace is now ignored, as spdx-tools ignores it, except inside a `<text>` block, where it is still part of the value
- fix SPDX JSON failing to load on `OPERATING-SYSTEM` (every trivy image sbom), `PERSISTENT-ID`, `$schema` and `revieweds`
- fix a version change whose two sides spell the package name differently coming out as one removed and one added component, so `--fail-on version-downgrade` missed the downgrade and `--fail-on removed-components` fired on a package that is still there: `PyYAML` against `pyyaml`, `typing_extensions` against `typing-extensions`, and an npm scope written as a CycloneDX `group` (`@types` + `react`, as trivy writes it) against the scoped name SPDX carries (`@types/react`). components whose purls parse now pair on the purl's type, namespace and name in the canonical form their ids already use; a purl renamed under one component name is still a purl change, and a component without a purl still matches on name alone. a purl that differs only in spelling, `pkg:pypi/PyYAML@6.0` against `pkg:pypi/pyyaml@6.0` or `%40angular` against `@angular`, is no longer listed as a purl change
- fix SPDX license and exception ids written in another case, such as `mit` or `gpl-3.0-only`, slipping past the license gates: `--deny-license GPL-3.0-only` let `MIT AND gpl-3.0-only` through, `--fail-on copyleft-added` missed it but fired on `gpl-3.0-only` -> `GPL-3.0-only`, `--allow-license MIT` rejected `mit OR Apache-2.0`, and `--fail-on license-changed` fired on `mit` -> `MIT`. ids now match case-insensitively, as SPDX specifies; `LicenseRef-` names still match exactly. `canonical_license_case` is exported from sbom-model
- fix an SPDX document and its CycloneDX twin reporting `Metadata changed` on the timestamp alone, which failed `--fail-on metadata-changed`: the SPDX reader printed `created` as `2010-01-29 18:30:22 UTC` where the CycloneDX reader printed `2010-01-29T18:30:22Z`, and trivy writes the same instant as `2026-10-23T13:40:35Z` in its SPDX and `2026-10-23T13:40:35+00:00` in its CycloneDX. both readers now print the timestamp as RFC 3339 in UTC, `2010-01-29T18:30:22Z`, so one instant reads the same in either format; a CycloneDX timestamp with another offset is shown in UTC, `2026-10-23T15:40:35+02:00` as `2026-10-23T13:40:35Z`, and one that is not RFC 3339 is shown as written
- fix an SPDX tag-value package section with no `PackageName:` line, which trivy writes for the root of a virtual-workspace Cargo project, being folded into the package above it, or dropped when no package is above it: its version, license and supplier replaced the other package's, so a diff showed that package as changed and the nameless one as missing, and trivy's tag-value sbom of a workspace read against its own SPDX JSON twin, which carries `"name": ""`, as a removed component and lost dependency edges, with `does not match any element` warnings. such a section is now read as a package with an empty name, as the JSON reader reads it
- fix an SPDX tag-value package with an empty name, which spdx-tools writes as a bare `PackageName: ` line, taking the line below it, such as `SPDXID: SPDXRef-Package-b`, as its name and losing its SPDXID: its dependency edges were dropped with `does not match any element` warnings, and a diff against its SPDX JSON twin reported a removed component, an added one and an edge change. such a package is now read with an empty name, as the JSON reader reads it

## [0.9.1] - 2026-10-14

- fix a warning on every SPDX relationship whose other end is a file, a snippet, `NONE` or `NOASSERTION`, or an element of a declared external document, none of which is a package and none of which is an error: a trivy `rootfs` scan of 301 npm packages printed 602 `does not match any package` warnings, one per file a package `CONTAINS`, and `--show-warnings` turned them into 602 SARIF results that buried the 2 real ones. these relationships are now skipped without a warning, as is a CycloneDX dependency on or of a service. a reference to nothing in the document still warns, and the SPDX warning now names the field (`spdxElementId` or `relatedSpdxElement`) and the relationship, so an inverse type such as `DEPENDENCY_OF` no longer calls its right-hand element the source. the dependency graph read is unchanged
- fix `--fail-on version-downgrade` missing a step from a release written with four or more parts down to its pre-release: `1.2.3.0` -> `1.2.3-rc.1` compared equal because the pre-release was ignored against the four-part side, though `1.2.3` -> `1.2.3-rc.1` and `1.2.3.0` -> `1.2.3rc1` were both caught. a pre-release now sorts below its release however many trailing zeros the release is written with, and an sbom carrying several versions of one package in the two shapes, `9.0.0.0`/`10.0.0.0` -> `9.0.1-rc.1`/`10.0.1-rc.1`, pairs them in version order instead of splicing a `10.0.0.0 -> 9.0.1-rc.1` downgrade
- fix a crash (exit 101, `user-provided comparison function does not correctly implement a total order`) on an sbom listing a few dozen versions of one non-PyPI package that mix semver pre-releases with PEP 440 spellings, such as `1.0.0-a1` and `1.0.0-dev1` next to `1.0.0a0`: a semver pre-release was ordered by semver against another one but by PEP 440 against the PEP 440 spelling, so `1.0.0-a1 < 1.0.0-dev1 < 1.0.0a0 < 1.0.0-a1`. the versions of such a package are now paired by component id, as other version mixes with no consistent order already are
- fix an SBOM that lists one package twice losing dependency edges: when two entries resolved to the same component, only the later entry's bom-ref or SPDXID was kept, so every relationship naming the earlier entry was dropped with a misleading `does not match any component` warning, and which edges survived depended on the order of the entries, so re-ordering them changed the dependency graph a diff reports. the later entry's fields still win, but the relationships of both entries are kept. alongside it: a CycloneDX `dependencies` list that names one parent twice merges the children instead of keeping only the last list; a relationship between two entries of the same package is still dropped, now without a warning, while a path from one entry through another package to the other is now a cycle that `--fail-on cyclic-dependency` reports (exit 3); and an edge read twice with different kinds no longer takes whichever came last in the document, in both formats the first of runtime, dev, build, test, optional and provided wins. `Sbom::insert_component` and `Sbom::insert_dependency` are added to sbom-model
- fix `--fail-on purl-changed` failing on every version bump of a component with a purl: the version is part of the purl, so `pkg:npm/left-pad@1.0.0` -> `pkg:npm/left-pad@1.1.0` counted as a purl change. the gate now compares purls without their version, so it fires on a renamed purl, a changed qualifier such as `repository_url` or a changed subpath, and not on qualifier order, percent-encoding or qualifier key case. the diff output still lists the purl difference of a version bump
- fix packages that only share a name being reported as one changed package: matching ignored the purl namespace, so a Maven artifact id in two groups (`org.jetbrains:annotations` 13.0 and `com.google.code.findbugs:annotations` 3.0.1) read as a `13.0 -> 3.0.1` downgrade that failed `--fail-on version-downgrade`, and npm packages sharing a last name segment (`react` and `@types/react`, `@babel/parser` and `@typescript-eslint/parser`) could swap versions between them. the purl namespace is now part of a component's identity, so such packages are reported as one removed and one added component; a component without a purl still matches on name alone. a relocation that only changes the namespace (`asm:asm` -> `org.ow2.asm:asm`) is a removed and an added component too, which `--fail-on added-components` catches and `--fail-on purl-changed` no longer does
- fix `--output markdown` letting SBOM text break out of its formatting in a PR comment: a backtick in a component id, version, hash or other value ended its code span early, a `|` in an ecosystem name split the ecosystem table, a line break ended the list item or heading it sat in, and a parser warning quoting `</details>` or other markup closed the collapsible section and injected html. values now render literally — code spans widen their backtick fence past any run inside the value, line breaks inside a value render as a space, and warnings and ecosystem names are escaped — while ordinary values render exactly as before
- fix added and removed components coming out in a different order on each run over the same two sboms, which made snapshot comparisons of the output flap; both lists, in every output format and in the `--fail-on added-components`/`removed-components` messages, are now sorted by component id, which is the purl where there is one

## [0.9.0] - 2026-09-12

- read CycloneDX 1.6 documents, in json and xml: the current spec since April 2024, and what syft, cdxgen, trivy and cargo-cyclonedx emit by default, was refused outright with "only 1.3–1.5 is supported". a 1.6 document is read under 1.5 rules, which loses nothing sbom-diff models — component name, version, supplier, purl, description, licenses and hashes, the metadata timestamp, tools and authors, and the dependency graph are unchanged between the two spec revisions — and every read of one emits a warning naming the version and the fields it drops. component `evidence` is one of them: 1.6 spells `evidence.identity` as a list of identities where 1.5 allows only one, and recommends the list even for a single identity, but a json document using that spelling failed to load at all — the whole document, over one component — with an `invalid type: map, expected a string` message naming neither the field nor the version. 1.7 and later still fail, and the message no longer names a range that stops at 1.5
- fix a CycloneDX XML document rejected as an unsupported spec version because the same namespace url appeared in a comment, in element text or in an unrelated attribute ahead of the root element's own declaration; the version is now read from the namespace the root element itself is in
- add `--fail-on checksum-changed`: fails (exit 3) when a matched component's digest changed under an algorithm both sboms record while its version stayed the same — a release re-published under the same version, or a moved tag. a version change is expected to bring a new digest and is never reported, an algorithm only one side records is not a value mismatch (dropping every checksum is still `missing-hashes`, weakening the strongest one is still `hash-algorithm-downgrade`), and digests are compared case-insensitively so the upper case CycloneDX permits and the lower case SPDX mandates are the same digest. `changed_checksums` is exported from sbom-model
- fix `--fail-on version-downgrade` for Alpine `apk` versions, which were compared as semver: the `-rN` package revision now ranks above the version it rebuilds instead of below it as a pre-release, and revisions compare as numbers, so a routine `1.2.3-r9` -> `1.2.3-r10` rebuild no longer fails the gate and a real `1.2.3-r10` -> `1.2.3-r4` rollback no longer passes it. `_alpha`/`_rc`/`_git`/`_p` suffixes and `~commithash` snapshots are ordered too, where before the pair was skipped as uncomparable
- fix `--fail-on version-downgrade` for Python versions: a `pkg:pypi/...` component is now ordered by PEP 440, so `1.0.2a` is the pre-release `1.0.2a0` that sits below `1.0.2` instead of a Debian upstream version that sits above it. the gate no longer misses a release-to-pre-release downgrade, and no longer fires on an upgrade like `1.0+0` -> `1.0r`
- fix SPDX tag-value documents whose package fields carry a multi-line `<text>` block: a `Creator:` line quoted inside one was adopted as a document creator and could suppress the phantom-creator warning, and a quoted `ExternalRef:` or `PackageName:` line switched the flush-sentinel warning on or off wrongly
- fix SPDX tag-value documents rejected outright as an unsupported SPDX version because a `<text>` block quoted an `SPDXVersion:` line ahead of the document's real one, as a `DocumentComment:` can; a document whose only `SPDXVersion:` sits inside a text block is now reported as having no version tag rather than taking the quoted one as its version. a `<text>` with no closing marker anywhere after it is not a block at all, matching the parser, so such a document still reports its version, creators and tools instead of losing every tag below it
- fix `--fail-on version-downgrade` for NuGet versions, which were ordered by a guess: release labels are compared case-insensitively, so `3.0.0-beta` -> `3.0.0-RC` is no longer reported as a downgrade and the .NET `preview` -> `rc` -> release ladder runs forwards; the fourth field is a real version field, so `2.0.0-rc` no longer compares equal to `2.0.0.0`; and `1.0.0-01` and `1.0.0-1` are the same version rather than an unorderable pair the gate waves through
- fix SPDX tag-value documents silently losing every component below a line the parser cannot read; such lines are now skipped and named in the parser warnings
- fix an unreadable `ExternalRef` category, checksum algorithm, `Relationship` type, `FileType` or `AnnotationType` aborting the run; the line is skipped and named too
- fix an empty or whitespace-only license expression aborting the run, on the tag's own line or in a `<text>` block; it is dropped and named, but a non-empty expression the SPDX expression parser rejects (`MIT AND`) still aborts
- report an SPDX tag-value document the parser still cuts short as an error naming the first package lost, never as a partial SBOM

## [0.8.0] - 2026-08-17

- gate licenses on the declared SPDX expression instead of a flattened identifier set: `--deny-license gpl-3.0-only` no longer blocks a `MIT OR GPL-3.0-only` component that can be taken under MIT, `--allow-license mit --allow-license bsd-3-clause` no longer rejects `(MIT OR Apache-2.0) AND BSD-3-Clause`, and `--fail-on copyleft-added` fires only when the new expression offers no way to satisfy it whose copyleft obligations the old one already offered, naming the copyleft the new side's least burdensome choices carry minus what the old side already forced — an unchanged `GPL-2.0-only OR GPL-3.0-only` choice is not an introduction, `MIT` -> `GPL-3.0-only AND (MPL-2.0 OR ISC)` names `GPL-3.0-only` alone because the ISC choice avoids `MPL-2.0`, and `MIT` -> `GPL-2.0-only OR AGPL-3.0-only` names both because neither choice avoids the other
- report a dropped or added `WITH` exception as a license change: `GPL-2.0-only WITH Classpath-exception-2.0` and bare `GPL-2.0-only` are no longer indistinguishable, and an exception is nameable in `--deny-license`/`--allow-license` by its full spelling
- report a license change whenever the two sides are satisfied by different sets of licenses, and only then: operand order and parentheses do not count, an expression that is a plain conjunction of its own identifiers matches a side that lists those identifiers without one, and collapsing `MIT OR GPL-3.0-only` into a bare `MIT`/`GPL-3.0-only` pair is a change that `--fail-on license-changed` and `--fail-on copyleft-added` both catch; an expression that expands to more than 64 alternatives is compared by its parse tree instead, where reordering operands does count as a change
- add `Component::license_expression` and `Component::licensing` plus `Licensing`, `LicenseRequirement`, `copyleft_obligations_added`, `license_expressions_equivalent` and `licensings_equivalent` to sbom-model, and `FieldChange::LicenseExpression` to sbom-diff; components carrying no expression are gated exactly as before, on their identifier set
- fix `--fail-on version-downgrade` for Debian and Ubuntu versions, which were compared as semver
- add `Version::parse_for_ecosystem`, `versions::compare_versions_for_ecosystem` and `versions::is_version_downgrade_for_ecosystem` to sbom-model, which take the component's ecosystem (a purl package type) and apply that ecosystem's version rules; a `None` or unrecognized ecosystem behaves exactly like the existing `Version::parse_lenient`, `compare_versions` and `is_version_downgrade`, whose signatures and results are unchanged. sbom-diff gains `pair_ecosystem`, which picks the ecosystem for a matched component pair and returns `None` when the two sides disagree
- fix `--fail-on version-downgrade` for PEP 440 versions, which were compared as Debian
- fix `--fail-on version-downgrade` for RPM versions like `4.4.2-2.el7_9`, which were not read as versions at all, so downgrades passed the gate silently; the ones that were read could still be ordered backwards
- fix `--fail-on version-downgrade` for Maven versions: a qualifier like `1.0-SNAPSHOT` could not be compared against its release at all, and `1.0-Final` -> `1.0-SNAPSHOT` was ranked as an upgrade. the dotted spelling Spring, JBoss, Hibernate and Netty publish (`1.0.0.CR1`, `2.0.0.Final`) orders as the hyphenated one, so `1.0.0.CR1` -> `1.0.0-CR2` reads as the upgrade it is

## [0.7.0] - 2026-08-08

- fix invented version downgrades when the same dependency set is diffed across serialization formats: components that gain or lose their purl are paired in version order, so an npm SBOM re-exported as purl-less SPDX reports no version change instead of a spliced `1.0.0 -> 2.0.0` upgrade and `2.0.0 -> 1.0.0` downgrade failing `--fail-on version-downgrade`
- read SPDX 2.x XML documents: `--format spdx-xml` parses them, `--format auto` detects them, and `SpdxReader::read_xml` mirrors `read_json`/`read_tag_value`. both `<Document>` and `<SpdxDocument>` roots are accepted; SPDX 3.x is rejected with the same unsupported-version message as the JSON and tag-value paths
- treat the SPDX `NOASSERTION`/`NONE` supplier sentinels as "no supplier", matching the license handling; previously they reported a bogus `Supplier: <none> -> NOASSERTION` change, failed `--fail-on supplier-changed` on it, and fed the identity hash of purl-less components, splitting the same package into an add/remove pair
- label hash-algorithm downgrades in text, markdown, and CSV output (`Hashes (algorithm downgrade)` / `hashes-downgrade`), matching SARIF and the `--fail-on hash-algorithm-downgrade` gate; ordinary hash changes keep the neutral label
- parse the CycloneDX `metadata.component` (the BOM's primary component): its name, version, purl, licenses, and hashes now appear in the diff, and dependency edges rooted at its bom-ref resolve instead of being dropped with `does not match any component` warnings. a component listed in both `metadata.component` and `components[]` is de-duplicated as before
- CSV `--summary` now emits parser warnings like the other formats, as a leading block in the same six-column schema as full CSV output
- fix ecosystem-filtered diffs reporting an `unchanged` count that could exceed the new side's total when a matched component's ecosystem changes across the filter boundary; `unchanged` is now derived from the new side, consistent with the added/changed counts
- add three `--fail-on` gates (exit 3): `purl-changed` and `ecosystem-changed` fire when a component that keeps its logical identity changes package coordinates (a typosquat/dependency-confusion signal), and `copyleft-added` fires when an update or new component introduces a copyleft license not present before, the direction `license-changed` buries in noise. copyleft is classified offline from the SPDX license list; `LicenseRef-` and unrecognized identifiers count as non-copyleft
- fix BOM-prefixed SBOMs failing to load: a leading UTF-8 byte-order mark is stripped before parsing and auto-detection; a file containing only a BOM is reported as empty input
- fix fabricated version downgrades when an SBOM carries two versions of the same package: components sharing name and ecosystem but no purl are paired in version order, so `libfoo@9.0.0`/`10.0.0` -> `9.0.1`/`10.0.1` reports two upgrades instead of a spliced `10.0.0 -> 9.0.1` downgrade, and edge reconciliation follows the corrected pairing. unorderable versions (opaque strings, mixed version schemes) keep their previous pairing, and an exact `(ecosystem, name)` match takes precedence over an ecosystem-less one
- add `Version::partial_cmp_lenient` and `versions::compare_versions` to sbom-model, exposing the lenient ordering `is_downgrade` already used; both return `None` when the ordering is unknown

## [0.6.0] - 2026-07-05

- warn when `--only` excludes a field that an active `--fail-on` gate depends on: `--only` is documented as an output filter, but it also narrows what the diff computes, so a combination like `--only license --fail-on version-downgrade` silently bypasses the gate — the version changes are never computed, no violation is found, and the process exits 0 despite a real downgrade; a warning now names each masked gate and the excluded field(s) so the silent CI/supply-chain no-op becomes visible. Affects the field-dependent gates (`version-downgrade`, `license-changed`, `supplier-changed`, `hash-algorithm-downgrade`, `missing-hashes`, `changed-components`, `deps`); structural gates (`added-components`, `removed-components`, `metadata-changed`, `cyclic-dependency`) are unaffected. Gate exit-code semantics are unchanged — this only surfaces the conflict
- make `--fail-on version-downgrade` correct for non-SemVer versions: build-metadata-only changes (e.g. `1.0.0+build.10` → `1.0.0+build.9`, or commit-hash metadata like `1.0.0+c144a98` → `1.0.0+bc17664`) are no longer flagged as downgrades — SemVer §10 excludes build metadata from precedence; and Debian/RPM-style versions carrying an epoch or revision (e.g. `2:1.0` → `1:9.0`, `5.1-3` → `5.1-2`), which dominate OS/container SBOMs and were previously treated as uncomparable and silently skipped, are now compared with the Debian version-ordering algorithm (epoch, then upstream version, then revision) so real epoch and revision downgrades are caught
- SARIF output now reports per-algorithm hash changes — naming which algorithms and digests were removed, changed, or added — instead of a bland `hashes changed`, matching the detail already emitted by the text, markdown, and CSV formats; a hash-algorithm downgrade (e.g. SHA-256 replaced with MD5) is now escalated to `error` level and annotated in the message, consistent with the `--fail-on hash-algorithm-downgrade` gate
- fix `--fail-on version-downgrade` silently missing downgrades of `v`-prefixed multi-segment versions: four-part (`v1.2.3.4`) and date-based (`v2024.01.15`) versions were misclassified as opaque (uncomparable) and slipped past the gate; they are now recognized as numeric versions so a downgrade like `v1.2.3.4` → `v1.2.3.3` is correctly flagged
- surface version downgrades in diff output: `ComponentChange` now carries an `is_downgrade` flag (computed via `sbom_model::versions::is_version_downgrade`), and all renderers visually distinguish downgrades from upgrades — text/markdown label the field `Version (downgrade)`, CSV uses the `version-downgrade` field name, SARIF escalates downgrade results to `error` level and annotates the version message, and JSON includes the `is_downgrade` boolean (omitted when false for backward compatibility)
- add persistent reverse dependency index (`reverse_deps`) to `Sbom`: `rdeps()` is now O(1) lookup instead of O(edges) full-graph scan, and `roots()` uses the index for O(n) instead of rebuilding a target set each call; the index is built automatically by parsers and `normalize()`, and can be rebuilt manually via `Sbom::rebuild_reverse_deps()` after modifying `dependencies`
- eliminate redundant `Component::clone()` calls in `Differ::diff_owned()` by splitting the diff into a decide-then-drain pipeline: match decisions are collected using borrows only, then matched pairs are moved out of the SBOM maps via `swap_remove` and unmatched remainders are drained with `into_values()`, avoiding all component clones during identity matching and reconciliation

## [0.5.0] - 2026-06-18

- warn when duplicate component IDs (purls or property hashes) cause silent overwriting in both CycloneDX and SPDX parsers; previously the parsers silently dropped the earlier occurrences with no diagnostic — now a warning is emitted naming both the existing and incoming component before the overwrite
- derive CycloneDX dependency kinds from the component `scope` field instead of hardcoding `DependencyKind::Runtime`: components with `scope: "optional"` now produce `Optional` edges, `scope: "required"` (or absent) produces `Runtime`; fixes silent kind mismatches in mixed-format diffs and incorrect `--fail-on deps` output for optional dependencies
- fix `parse_license_expression` dropping `LicenseRef-` identifiers from mixed SPDX expressions: expressions like `LicenseRef-proprietary AND Apache-2.0` were collapsing to just `Apache-2.0`, causing `--deny-license` to miss LicenseRef terms and license diffs to be inaccurate; both standard SPDX IDs and LicenseRef identifiers are now correctly decomposed
- add `--fail-on cyclic-dependency` CI gate: detects dependency cycles in the new SBOM's dependency graph using DFS-based cycle detection; reports each cycle with the full component path; add `Sbom::detect_cycles()` to sbom-model for programmatic use
- fix `--include-ecosystem` and `--exclude-ecosystem` leaving `edge_diffs` unfiltered: dependency edge changes are now filtered by the parent component's ecosystem, and stale `component_names` entries are pruned after filtering; `Diff::filter_by_ecosystem()` signature now takes a `component_ecosystems` map to support edge diff filtering
- add content-based format detection heuristics to auto-detect mode: pre-scans input for format markers (`"bomFormat"` for CycloneDX JSON, `cyclonedx.org/schema/bom` namespace for CycloneDX XML, `"spdxVersion"` for SPDX JSON, `SPDXVersion:` header for SPDX tag-value), tries the likely format first, falls back to remaining parsers, and provides targeted error messages naming the detected format on failure; rejects empty files and binary input (null bytes) with clear diagnostics
- add `--fail-on hash-algorithm-downgrade` CI gate: detects when a changed component's strongest hash algorithm is weaker than before (e.g. SHA-256 replaced with MD5), using a strength ordering across known algorithm families (MD < SHA-1 < SHA-224 < SHA-256/SHA3-256/BLAKE2b-256/BLAKE3 < SHA-384 < SHA-512); complements `--fail-on missing-hashes` which catches completely dropped hashes
- add `--include-ecosystem` and `--exclude-ecosystem` flags to filter diff output by package ecosystem
- add `Diff::filter_by_ecosystem()` for programmatic ecosystem filtering
- add `--output csv` (RFC 4180 CSV) output format for spreadsheets, CI dashboards, and data pipelines: full output produces one row per finding with columns `status,component,ecosystem,field,old_value,new_value` covering added/removed/changed components, edge diffs, and metadata changes; `--summary` mode produces compact `metric,count` pairs with an optional `ecosystem,added,removed,changed` breakdown when `--group-by-ecosystem` is set; CSV escaping handled by the `csv` crate
- add `--fail-on supplier-changed` CI gate: detects when a changed component's supplier field differs between SBOM versions or when an added component introduces a supplier; designed to catch supply-chain takeovers (like the xz incident) where a package's maintainer/supplier changes unexpectedly

## [0.4.0] - 2026-06-08

- extract version comparison logic (`parse_version_lenient`, `is_version_downgrade`) from the CLI binary into a public `sbom_model::versions` module with a `Version` enum (`Semver`/`Numeric`/`Opaque` variants), `parse_lenient()` constructor, and `is_downgrade()` method; the `semver` dependency moves from `sbom-diff` to `sbom-model`; cross-variant comparison (e.g. semver `v1.2.3` vs four-part `1.2.3.4`) now works correctly instead of bailing
- fix SARIF renderer ignoring `--show-warnings`: parser warnings are now emitted as note-level `parser-warning` results with source-labeled locations (`old-sbom`/`new-sbom`), making them visible in GitHub Code Scanning and other SARIF consumers; previously the SARIF renderer prefixed its `opts` parameter with underscore and discarded it
- add `--fail-on version-downgrade` CI gate: detects when a changed component's version goes from a higher to a lower value, using lenient semver parsing (handles `v` prefixes, two-part versions, pre-release tags) with a dot-separated numeric fallback for non-semver strings like date-based versions (`2024.01.15`) or four-part versions (`1.2.3.4`); returns `false` (no downgrade) when version ordering cannot be determined
- add `Differ::diff_owned()` consuming variant that normalizes SBOMs in place, avoiding two full SBOM clones when the caller owns the inputs; the CLI now uses this path, and `Differ::diff()` delegates to it
- deduplicate `Diff::group_by_ecosystem()` / `into_group_by_ecosystem()` via a shared `group_components_by_ecosystem` helper that accepts owned iterators
- surface silent parser failures with structured diagnostic context: CycloneDX depth-truncation warning now names the dropped component(s) and depth level; CycloneDX XML multi-version retry emits a warning when it falls back to an older spec version; SPDX tag-value parser warns when the flush-sentinel workaround fires (last package has ExternalRefs) and when phantom creators from spdx-rs 0.5 defaults are stripped
- add `--output sarif` (SARIF 2.1.0) output format for GitHub Code Scanning and Azure DevOps integration: maps component additions, removals, and field-level changes to SARIF results with five rules (`component-added`, `component-removed`, `component-changed`, `dependency-changed`, `metadata-changed`); each result includes a `locations` array with `logicalLocations` (package identifier for component rules, parent identifier for dependency rules, `metadata` for metadata rules) so results appear in GitHub Advanced Security and CodeQL; no new dependencies — SARIF JSON is built with the existing `serde`/`serde_json` types
- fix SARIF renderer emitting an empty `"Metadata changed: "` result when `MetadataChange` has no populated subfields; the result is now skipped when all subfields are `None`
- replace `metadata_changed: bool` with structured `MetadataChange` tracking that records exactly which metadata fields differ (timestamp, tools, authors) with old/new values; rendered as a new `[~] Metadata Changes` section in text output, a collapsible `<details>` block in markdown, and a structured `metadata_changed` object in JSON; summaries show a `Metadata changed: yes/no` line; add `--fail-on metadata-changed` CI gate that fails when any document metadata differs, reporting which specific fields changed
- fix `--fail-on deps` not reporting `kind_changed` edges in error messages: when a dependency changed kind (e.g. dev→runtime), the violation exit code fired but no error message explained which edges changed; now prints `error: dependency edge ... changed kind: dev -> runtime (--fail-on deps)` for each affected edge
- fix `FieldChange::Version` collapsing absent versions to empty strings: version now uses `Option<String>` to preserve the distinction between a version being absent (`None`) and being empty, so a component going from no version to `1.0` renders as `<none> -> 1.0` instead of ` -> 1.0`
- add `Edge changes` and `Metadata changed` rows to the full render summary headers (text and markdown) for consistency with `--summary` mode, which already showed them
- replace `.expect()` calls in JSON summary renderer with `?` error propagation, matching the project's error handling patterns

## [0.3.0] - 2026-05-21

- consolidate `render_summary_text`/`render_summary_markdown`/`render_summary_json` into a `SummaryRenderer` trait (mirrors the existing `Renderer` trait); all summary rendering logic now lives in the `renderer` module, making new output formats trivial to add

- show per-parser rejection reasons when `--format auto` fails to detect the SBOM format, instead of the generic "could not detect sbom format automatically" message
- strip SPDX supplier prefixes (`Organization: `, `Person: `) during parsing so cross-format diffs no longer produce false positives
- add `Diff::is_empty()` convenience method
- optimize `by_purl()` from O(n) linear scan to O(1) via direct `ComponentId` lookup
- show per-algorithm hash diffs (algorithm, old digest, new digest) instead of the generic "Hashes: changed" message in all output formats (text, markdown, JSON)
- fix text and markdown renderers showing Rust debug format (`Some("MIT")`, `None`, `{"MIT"}`) for License, Supplier, Purl, and Description fields; these now display as plain strings with `<none>` for absent values
- optimize edge diff computation from O(n²) to O(n) by building a reverse ID map upfront instead of linear-scanning per parent
- add description field change tracking to the diff engine: the `description` field is now compared between SBOM versions and reported in all output formats; supports `--only description` filtering
- fix case-insensitive license matching in `--deny-license` and `--allow-license`: SPDX license IDs are case-insensitive by spec, but were compared with exact string equality, so `--deny-license GPL-3.0-only` would miss `gpl-3.0-only`
- map SPDX package description fields (`packageDetailedDescription` / `packageSummaryDescription`) into `Component.description`, fixing a data loss gap vs CycloneDX
- fix SPDX hash algorithm names to use canonical format (e.g. `SHA-256` instead of `SHA256`), so cross-format comparisons with CycloneDX no longer silently miss matching hashes
- move hash algorithm name normalization (`canonical_algorithm_name`) to the shared `sbom-model` crate and apply it in both SPDX and CycloneDX parsers, ensuring algorithm names always match regardless of source format
